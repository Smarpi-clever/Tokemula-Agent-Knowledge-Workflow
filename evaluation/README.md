# 固定本地检索评测

```sh
python3 -B scripts/evaluate_retrieval.py --output .local/v0.3.0/evaluation
```

语料和评分于 2026-11-05 固定，先于 v0.3 检索实现完成。`corpus.json` 包含 13 个人工主题和 2 个通过真实 `Engine.submit` 验证保存的事实主题，共 15 个主题。所有文本均为合成材料。`queries.json` 固定 12 条查询、相关主题、结果数量 5 和 6000 UTF-8 bytes 输出预算。

## 比较口径

基线固定为 `2ac1ee2411e8345ec6043bab907a4b6a5b25af5f`（v0.2.2）。脚本通过 `git archive` 提取该版本，在隔离目录生成相同的正文、来源文件、替代顺序和查询；基线使用 `Engine.context(task)`，v0.3 使用正式 `SearchIndex.search` 接口。两版均通过各自的引擎保存合成事实，展示用元数据随各版格式保留。

- **Recall@5**：对 11 条有相关主题的查询，取原生返回的前 5 个结果，计算命中的相关主题比例后宏平均。重复片段不增加命中数。
- **MRR@5**：上述查询第一个相关主题的原生结果排名倒数，缺失计 0，宏平均。
- **无结果正确性**：固定无关查询应返回空列表，单独报告。
- **旧状态**：分别记录显式历史查找能否展示已替代版本、默认结果是否将旧版作为当前内容，以及检索接口是否提供判定所需的状态标签。基线只返回主题元数据，旧状态标注记为缺失，实际旧内容误用记为未知。
- **待复核**：已经验证的源文件在查询前发生变化；结果应显示待复核状态。
- **人工修改**：先查询尚未包含关键词的主题，再追加固定人工段落，随后再次查询。正文命中计入同一评分。
- **上下文大小**：记录原生接口完整 JSON 的 UTF-8 bytes，同时报告前 5 个原生结果的 JSON bytes。v0.2.2 原生 context 会返回全部主题，v0.3 search 使用固定数量与字节预算。
- **耗时**：进程内先预热索引，然后逐查询运行 5 次，报告中位数毫秒；另以实际 CLI 启动 3 次报告包含 Python 启动的中位数。耗时依赖本机负载，指标使用相同运行环境。

无相关查询不参与 Recall/MRR 分母。历史查询请求 `history=true`，其他查询使用默认当前模式。Token 数未估算。完整原生结果、逐项分数、失败样例、正确性判定和汇总保存到输出目录的 `report.json` 与 `report.md`；评测会保留失败项。

改动本固定集时应建立新的评测版本。修复实现可沿用此语料与口径重跑。
